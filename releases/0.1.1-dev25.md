# Juna 0.1.1-dev25

Drag a tab out of the strip and it moves into its own window. Release below the strip and the
tab opens in a new native window with the same shell still running: scrollback, working
directory, cursor and view state move with it, because the session is moved as a value inside
the process rather than restarted.

While the pointer is below the strip, the strip shows an accent edge and a "Release to open in a
new window" hint, and the reorder band disappears, so the two outcomes cannot be confused. A
window with a single tab refuses the gesture: the tab stays where it is and no detach affordance
appears.

Detached windows keep working. Each window owns its engine and renderer, and the application
pumps every window, so a detached window keeps draining shell output and closes when its session
ends. Closing the window you are using promotes another one instead of exiting.

Protected Junafetch fields follow their tab into a detached window. Close detached windows
before installing an update: they share the process that must exit for executable replacement.
The reported dev23 update problem remains under investigation; this release does not claim to
fix it. Theme changes after detachment currently apply to the current window only, and mixed-DPI
monitor transitions still need separate work.

Validation on 2026-10-23: required check, strict all-target Clippy and the full standard suite
passed (239 library tests and 24 other tests). Explicit desktop acceptance verified two detached
sessions consuming their final output and closing normally. An isolated in-place update with
the current helper and a stripped debug build replaced dev11 with dev25, acknowledged restart,
and preserved user files/preferences. This does not establish the cause of the reported shipped
dev23 updater failure. The physical drag gesture and typing into a detached window still need
human acceptance. Hosted builds and downloadable assets are verified after tagging.
