# Juna 0.1.1-dev24

Dragging a tab now shows where it is going. The dragged tab's slot is drawn as an outline that
follows the pointer, and the destination is a translucent accent band with the insertion marker,
so the landing position is visible before release. The outline is clamped to the tab strip and
never covers the new-tab button.

The highlight and marker come from the same resolved drop gap as the reorder itself, so they
cannot point somewhere the tab will not land. Reordering still moves tab records only: the
running session, engine and scrollback stay with the tab.

Detaching a tab into a new window by dragging it out of the strip is not implemented. It is
designed in `TAB_DRAG_DETACH_DESIGN.md` and requires moving window-local state into per-window
workspaces; a ConPTY session cannot be handed to another process without duplicating handles and
serialising parser state.

Validation: check, strict all-target Clippy and the standard lib suite passed (236 passed, 2
ignored). New tests cover outline clamping at both strip edges, band and marker alignment at
both ends of the strip, and unchanged rendering with no drag active. The gesture is a pointer
interaction, so visual acceptance requires recorded manual evidence; release assets are verified
after tagging.
